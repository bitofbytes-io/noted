IMSLP hand-off: search in Noted, download on IMSLP, PDF back in the draft

Only the IMSLP connection inside the Source step changes. The local work catalogue and its refresh job go away; the search field queries IMSLP directly through the Noted API. Choosing a work opens its IMSLP page in a new tab, where edition choice, the disclaimer and the download stay. The draft waits in Noted for the file.

Companion plan: docs/product/imslp-live-search-plan.md. The first frame is interactive so the debounce and limit behaviour can be felt, not just read.

    —
    • Minimum 2 characters. Below that: no request, results cleared, idle hint shown.
    • Identical consecutive query is skipped; the last 20 queries are cached in the page so backspacing is instant.
    • A newer keystroke cancels the in-flight request; a stale response is ignored.
    • Server side: per-user 2 req/s burst 4, outbound 5 req/s to IMSLP, 20-minute cache, circuit breaker after 3 upstream failures. See the plan.
    • The work-link field and Add downloaded PDF are always available. Search failing never blocks intake.

    On iPad this opens Files; Safari saves to Downloads.
    • The panel becomes a drop target while a work is chosen (desktop drag from the Downloads shelf). Dropping routes through the same code path as the file input.
    • Filenames from IMSLP start with the file number (IMSLP01240-…). When it is present, Noted can confirm the match against the chosen work; the check is informational and never blocks adding a file.
    • After the file is added, the existing flow continues unchanged: Pages (reorder, crop, extract) then Details.
    • Follow-upOn iPad the fastest path is the Share sheet from Safari's PDF viewer to a Send to Noted shortcut, which posts the file to the waiting draft. That needs a per-user token and a token-scoped endpoint, and is a separate issue. This frame is designed so its copy can later add "or share it from Safari with Send to Noted".
